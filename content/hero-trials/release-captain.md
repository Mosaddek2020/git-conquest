## brief | Release captain

**The scenario.** You maintain `beacon/beacon`, a monitoring agent. A first-time contributor, Jules, sent pull request #2 from their fork: it fixes the retry backoff bug reported in issue #1. Today is release day for **v1.5.0**.

Your job, start to finish:

1. **Review** the pull request properly: what it changes, whether CI is green, and whether it works on your machine.
2. **Approve and merge** it so the history stays clean and issue #1 closes itself.
3. **Credit** Jules in the changelog.
4. **Tag** v1.5.0, **signed**, so users can verify the release came from you.
5. **Publish** the GitHub release with notes.

No step tells you the exact commands. Everything you need is in earlier realms and in the Field Guide.
