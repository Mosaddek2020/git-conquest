## brief | Upstream contributor

**The scenario.** You use `tinyhttp/tinyhttp` at work and found a bug: redirects can loop forever. The project welcomes pull requests from forks and has two rules in CONTRIBUTING.md: **every commit carries a `Signed-off-by` line**, and **one commit per fix**.

Make the contribution the maintainers hope for:

1. **Fork** the project and clone your fork, with the original as `upstream`.
2. **Fix** it on a topic branch in one signed-off commit, push to your fork and open a pull request.
3. **Respond to review.** The maintainer will ask for a test. Add it as a fixup.
4. **Stay current.** `upstream/main` moves while you wait. Rebase onto it and fold the fixup in, so the pull request is still one signed-off commit.
5. **Update the pull request safely** and tell the reviewer what changed.
6. **Clean up** after the merge: your fork's `main` matches upstream and the topic branch is gone.
